Case Structuring Basics

Break a complex client question into focused, answerable parts.

Source
180DC IIM Indore
Level
Beginner
Format
Practical guide

In this guide

  1. Pin down the decision
  2. Create an issue tree
  3. Prioritise hypotheses
  4. Synthesize continuously
  5. Mini example
01

Pin down the decision.

Before drawing a framework, restate the objective in decision-ready terms. A clear problem statement prevents the analysis from expanding without purpose.

  • Confirm the objective, success metric, time horizon, and constraints.
  • Ask what decision the analysis must enable.
  • Separate visible symptoms from the underlying problem.
02

Create a tailored issue tree.

Start with the outcome and divide it into its main drivers. Aim for MECE branches: distinct enough to avoid double counting and collectively sufficient for the decision.

  • Choose branches that reflect this client and this decision.
  • Continue splitting until each branch can be tested with evidence.
  • Use familiar frameworks only when they fit; do not force the case into a memorised template.
03

Form and prioritise hypotheses.

An initial hypothesis gives the analysis direction, but it is not a conclusion. Update it as evidence arrives.

  • Rank branches by likely impact, uncertainty, and ease of testing.
  • Attach a specific question or data need to each priority branch.
  • State what evidence would change your current view.
04

Synthesize continuously.

After each analysis, explain what changed and why it matters. Evidence becomes useful only when it reconnects to the original objective.

  • Summarise the answer before describing the work.
  • Separate confirmed facts, interpretations, and remaining unknowns.
  • End with an action, supporting rationale, key risk, and next test.

Mini example

Annual donations are declining

Start by separating the drivers of annual donation value.

Active donors x gifts per donor x average gift

If active donors fell 18% while gift frequency and average value remained stable, prioritise donor acquisition and retention. Compare conversion and retention by cohort before recommending action.

Apply the structure to a quantitative problem.
